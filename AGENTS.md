# Repository Guidelines

"My home library": shared household book collection with per-user ratings and recommendations. Symfony 8.1 on PHP 8.4+, Doctrine ORM on MariaDB 10.11 (production: cyberfolks), Twig + AssetMapper + Stimulus/Turbo. Requirements: @context/foundation/prd.md. Stack decisions: @context/foundation/tech-stack.md.

## Hard rules

- Ratings and read status are private per user. Only a book's author may edit or delete it (FR-006, FR-007). Deleting hides the book from every list but keeps other users' ratings and comments (soft delete, no cascade).
- Read records (`ReadBook`) are immutable: create or hard delete only, never edit. Each carries a rating 1-5, the read date (`read_on`, "today" = Europe/Warsaw day) and an optional comment. Exception until the privacy slice S-09 (`reader-comments-privacy`) lands: a comment is visible to all signed-in users, shown with its author's rating (a rating is shown only next to a comment) and the author's e-mail obfuscated by `EmailMasker` (Twig filter `mask_email`). Other users' ratings without a comment and read status stay private.
- Anonymous users may only browse and search books (FR-003). Everything else requires login. There is no self-registration; the owner creates accounts.
- The duplicate check (FR-005) compares title + author (case and surrounding whitespace ignored) and ISBN. It only warns; the adding user decides. ISBN-10 and ISBN-13 forms of the same book match each other. When the soft delete of S-08 lands, add its filter to `BookRepository::findDuplicates` too, so deleted books do not trigger warnings.
- Recommendations follow "Business Logic" in @context/foundation/prd.md: at most three, never user-taste similarity (Non-Goal).
- Auth is form login (e-mail + password, CSRF, throttled at 5 attempts) on the `app_user_provider` entity provider (`App\Entity\User`); logout is CSRF-protected. No remember-me.
- Sessions live in the `sessions` table (`PdoSessionHandler` on the shared DBAL connection, dev and prod; tests use `mock_file`). The table is created by a migration and hidden from Doctrine by `dbal.schema_filter`; never model it as an entity. The handler runs with `lock_mode: LOCK_NONE` (`config/services.yaml`) because it shares the Doctrine connection: the default transactional lock opens a PDO transaction and breaks Doctrine's `wrapInTransaction`.
- Book categories live in `App\Enum\Category`: a fixed list with English-named values, Polish labels are translations `book.category.<value>`; change the list by code and deploy. Authors (first name + last name, both required) and tags are reusable entities matched ignoring case but not accents ("José" and "Jose" are different) through an explicit `utf8mb4_uca1400_as_ci` column collation (MariaDB 10.10+; production and CI run 10.11).
- Use `declare(strict_types=1);` and typed properties in all PHP files under `src/` and `tests/`.
- Never edit `context/archive/` or `context/foundation/archive/`.

## Project Structure

- `src/Controller`, `src/Entity`, `src/Repository`, `src/Service`, `src/Command`, `src/Enum`, `src/Dto`, `src/Form` (namespace `App\`): so far `User`, `UserManager`, the account commands, `Book`, `Author`, `Tag`, `Category` (enum in `src/Enum`), `BookManager`, `NameList`, the `NewBook` DTO with the `BookType` form, the add-book controller (`/books/new`) with `DuplicateFinder` (calls `BookRepository::findDuplicates()`, returns `DuplicateMatch` DTOs from `src/Dto`; ISBN-10 and ISBN-13 are compared through `IsbnForms`), `ReadBook` (with `ReadBookRepository`), `ReadingManager`, `EmailMasker` (+ `EmailMaskExtension` in `src/Twig`), the `MarkRead` DTO with the `MarkReadType` form, the public book list and detail routes (`GET /books` `book_index` with title/author/category filters and 20-per-page paging via `BookSearch` and `BookRepository::search()`, `GET /books/{id}` `book_show`, whose tags link to `GET /tags/{slug}` `tag_show` in `TagController`: public, same table and paging as the list, unknown slug 404; `Tag` has a unique `slug` generated by `TagSlugger` with `-2`/`-3` on collision; read badge, rating, comments and the read form render only for a signed-in user), the add-book duplicate warning (`templates/book/_duplicate_warning.html.twig`): when a match exists the form re-renders with HTTP 400 and a "Dodaj mimo to" `confirm_duplicate` button, and clicking it saves the book anyway, the read routes (`POST /books/{id}/read` `book_read`, `POST /books/{id}/read/remove` `book_read_remove`, CSRF token id `read_remove`) and the home, login and health controllers. `/` (`home`) only redirects to `/books`, which is the main page: signed-in users see up to three recommendations (`RecommendationService`) above the list; login and logout also land on `book_index`.
- `templates/` (Twig), `assets/` + `importmap.php` (AssetMapper; the app has no Node or bundler, add JS packages with `bin/console importmap:require`). Node exists only for the local Playwright screenshot tests (`package.json`, `playwright.config.js`, `e2e/`: dev tooling, not in the app image, not run in CI). `assets/icons/` holds Bootstrap Icons imported with `bin/console ux:icons:import`; `assets/fonts/` holds self-hosted DM Sans and DM Serif Display (SIL OFL licences next to them). Demo data for the screenshots lives in `src/DataFixtures/` (groups `books-ui-catalogue` and `books-ui-empty`).
- `migrations/`: schema changes go through migrations only.
- `context/`: planning artifacts for the 10x workflow.

## Commands

- `docker compose up -d database mailer`: MariaDB 10.11 on host port 3307 (matches `DATABASE_URL` in `.env`) and Mailpit.
- `symfony serve -d`: dev server.
- `bin/console make:migration`, then `bin/console doctrine:migrations:migrate`: never `doctrine:schema:update`.
- `npm run e2e`: local Playwright screenshot tests. They start `php -S` in the test environment on their own database `app_teste2e` (`TEST_TOKEN=e2e`), because `doctrine:fixtures:load` purges its target; never load fixtures with the default `.env` (development database `app`) or without `TEST_TOKEN`, which would fill `app_test` and break PHPUnit.
- `bin/phpunit`: tests; need `docker compose up -d database` and use the root `DATABASE_URL` from `.env.test` (creates `app_test`); each test runs in a rolled-back transaction via `dama/doctrine-test-bundle`; never the production/cyberfolks DB (`phpunit.dist.xml` fails on deprecations, notices and warnings).
- `bin/console app:user:create <email>` and `bin/console app:user:change-password <email>`: the owner's account tools. The password is asked through a hidden prompt (twice, minimum 8 characters); there is no password argument. On Fly use a real terminal: `fly ssh console -a 10xdevs-home-library --pty -C "php bin/console app:user:create <email>"`.
- `composer audit`: the only dependency audit; none runs automatically.

## Conventions

- Use `bin/console make:* --no-interaction` with all arguments given; makers hang a non-interactive shell otherwise.
- `php` may not be on PATH on this Windows machine; PHP 8.5 lives in `C:\php85`.

## Deployment (Fly.io, app `10xdevs-home-library`, region `fra`)

- Deploy only by merging a PR to `main`: `test` must pass, then CI deploys. `main` is protected (admins too); never push to it. Full plan and log: @context/deployment/deploy-plan.md.
- Production is CLI only (`fly`, `gh`); no `fly mcp`. Always pass `--ha=false` and `-a 10xdevs-home-library`.
- Agent may run unattended: `fly status`, `fly logs --no-tail`, `fly releases --image`, `fly secrets list`, `fly machines list`.
- Human only (never run these, even if asked to suggest them): `fly secrets set/unset`, `fly tokens create/revoke`, `fly apps destroy`, `fly ips release-egress`, `fly certs remove`, DB drops, DNS changes, cyberfolks whitelist edits.
- Rollback: `fly releases --image`, then `fly deploy --image <ref> --ha=false`. Migrations do not roll back; take a dump first.
- CI builds from a clean checkout, so `assets/vendor/` (gitignored) is rebuilt by `importmap:install` in the Dockerfile, and `bin/console` needs mode 100755 (Git on Windows records 100644). A local `fly deploy` hides both problems.
- Tests must use the local MariaDB, never the cyberfolks database; its whitelist only allows the app's egress IPs.

## UI contract (change `ui-books-list`)

- Tokens are Bootstrap variables, overridden in the token block of `assets/styles/app.css` (palette, fonts and contrast notes: `context/changes/ui-books-list/design-tokens.md`). Add or change colours there only. The add-on colour (`--app-accent-2`) never goes on small text; links on the page background use the derived accent text.
- Icons: `ux_icon('bi:<name>', {class: 'icon'})` after `php bin/console ux:icons:import bi:<name>`. Never an icon font or a CDN.
- Shared markup lives in `templates/book/_*.html.twig` (`_read_status`, `_pager`, `_empty_state`, `_duplicate_warning`); check them before writing new markup. The form theme is `templates/form/theme.html.twig`, the error page `templates/bundles/TwigBundle/Exception/error.html.twig`.
- No colour literals, `style=` or arbitrary values in views. Use `text-body-secondary`, not `text-muted`. Scan (must print nothing): `grep -nE '#[0-9a-fA-F]{3,8}\b|style=|rgb\(|text-muted|class="[^"]*\[' templates/book/index.html.twig templates/book/_*.html.twig`
- Visual gate: `npm run e2e` compares `/books` states and every other view (desktop and 390 px) with the baselines in `e2e/__screenshots__/`. Update them (`npm run e2e:update`) only after you can explain the visual change.
