# Home Library Management System — Shape Notes

## Vision & Problem Statement

**Problem:** You own many books at home but struggle to remember which ones you've read, what they were about, and whether you enjoyed them. This creates friction when buying new books (risk of duplicates), searching for something to read (what haven't I read yet?), and deciding whether a book is worth revisiting.

**Vision:** A personal library system that catalogs your books and uses your reading history and preferences to suggest what to read next.

**Why it matters:** The system learns your taste from what you've read and liked, then makes recommendations based on your defined criteria (genre, rating, notes). This transforms a static catalog into an active reading guide.

**Problem category:** Workflow friction — the process of remembering, organizing, and finding books is tedious.

**Key insight:** Personalized recommendations based on your taste distinguish this from a plain CRUD list. The app decides what to suggest; the user doesn't have to remember everything.

## User & Persona

**Primary persona:** You — an individual who collects and reads books, wants to keep track of your library, and would like intelligent suggestions for what to read next.

**Scope:** Personal project. Each user has their own library; users can invite others to see their collection and notes.

## Access Control

**Authentication:** Email + password login. Users create accounts and authenticate via email/password. Data is stored server-side.

**Authorization:** Flat model — all invited users have equal rights. No distinction between owner, member, or guest roles. All co-users can see, add, edit, and delete books and notes within the shared library.

## Success Criteria

### Primary (Must-Have)

**Working MVP flow:**
1. User logs in with email + password
2. System verifies credentials and issues access token
3. User sees dashboard with three sections:
   - Personal library (list of books user has added)
   - Add new book button
   - 3 book recommendations (generated by AI agent based on user-defined criteria)
4. User can add a new book to their library
5. Recommendations appear based on previously read books

**Timeline:** 4–5 weeks of after-hours work (7 hours/week)

### Secondary (Nice-to-Have)

- User can rate/review books they've read (1–5 stars, optional notes)
- Filter books by genre or read status (read/unread)

### Guardrails (Must Not Break)

- User authentication is secure (passwords hashed, tokens validated)
- User data is private — each user sees only their own library
- Recommendations are deterministic and explainable (user understands why they're suggested)

## User Stories

### US-001: First-time user discovers recommendations

```
Given: User has logged in and added 2 books, marking both as read with high ratings (4–5 stars)
When: User views their dashboard
Then: User sees exactly 3 book recommendations that match genres/themes they rated highly
And: User can understand why each book was recommended (based on their rated books)
```

## Business Logic

**Recommendation Rule:**
The application analyzes the user's reading history from the last 365 days, identifies the book genre with the highest average rating, and recommends 3 unread books from that genre. If fewer than 3 books exist in that genre, the app cascades to the next-best genre. If the user has no read books yet, a message appears: "Read a few books to get recommendations."

## Non-Functional Requirements

- **Data Privacy:** User's library data (books, ratings) is private and accessible only to the user and explicitly invited co-users. No third-party access.
- **Sensitive Data Encryption:** User passwords are securely hashed (bcrypt/PBKDF2); encryption is applied to authentication credentials only, not to book data.
- **Recommendation Performance:** Book recommendations are generated and displayed within 2 seconds of user request.
- **Data Integrity:** All user-provided data (ratings, book details) are validated and persist reliably in the database.

## Product Framing

**Product Type:** Web application. Users access the library via a web browser, log in, and manage their books from any device with internet.

**Target Scale:** Small — personal project for the user and a handful of invited co-users. No plans for public scaling or mass user acquisition in MVP.

**Timeline:** No hard deadline. After-hours work only (7 hours/week estimated). MVP scope: 4–5 weeks.

## Non-Goals

What this MVP explicitly does NOT do:

- **Not a public service:** This is a personal library, not a marketplace or community platform. No public sharing, no community recommendations, no open access.
- **No external integrations:** We do not integrate with Google Books API, Goodreads, or other services. Book data is entered manually.
- **No offline support:** The application requires internet connectivity. Data lives on the server; offline sync is not a v1 feature.
